# Anima Merger 1.1

Локальный инструмент для моделей **Anima** (2B — 28 блоков, 2.9B — 40 блоков). Он умеет:
- мерджить модели;
- вшивать и извлекать LoRA;
- переносить файнтюны между 2B и 2.9B;
- конвертировать файлы LoRA;
- **анализировать** модели и LoRA с наглядными HTML-отчётами.

Всё работает на твоём компьютере. Исходные файлы только читаются, результат всегда пишется в новый файл.

🇬🇧 [English version](README.md)

## Быстрый старт

**Windows**
1. Распакуй папку в любое место. Желательно, чтобы в пути не было кириллицы.
2. Запусти `install.bat`. Он создаст `venv` и поставит torch (сборка для процессора, около 200 МБ), gradio и safetensors. Нужен Python 3.10–3.12.
3. Необязательно, но для видеокарт NVIDIA советую: запусти `install_cuda.bat`, чтобы поставить torch для видеокарты. Анализ и извлечение LoRA станут в разы быстрее.
4. Запусти `run.bat`. Интерфейс откроется на `http://127.0.0.1:7887`.

**Linux:** `./install.sh`, потом `./run.sh`.

Вверху укажи папки моделей, LoRA и вывода и нажми **«Обновить списки»**. Папки запоминаются в `settings.json`. Переключатель языка (English / Русский) — справа вверху. После переключения программа сама перезапускается.

## Что умеет

| Вкладка | Зачем |
|---|---|
| **Мердж / замена базы** | `A + (B − C) × M` для моделей одной архитектуры. Режимы: `add`, `topk` (только самые сильные изменения), `dare`, `ortho` (без части, параллельной весам A), `ortho_delta` (без того, что A уже взяла от C: нет двойной дозы, когда у A и B общий предок; `--proj` задаёт, сколько убрать), `normdir`. Можно задать несколько M сразу — будет по файлу на каждое значение. |
| **Вшить LoRA** | Одна или несколько LoRA / LoHa / LoKr. Понимает форматы kohya, diffusion-pipe и ComfyUI. Есть множители по блокам и слоям, ограничитель от пережарки и сетка силы. LoRA от 2B на модели 2.9B раскладывается сама. |
| **Извлечь LoRA** | LoRA из разницы двух моделей (SVD) с оценкой точности. |
| **Смешать LoRA** | Несколько LoRA в один файл без модели: `concat` (точно, ранг = сумма рангов) или `svd` (сжатие до нужного ранга, точность покажет в логе). Правила по блокам — например, композиция от одной LoRA, линия и фактура от другой. |
| **Конвертер LoRA 2B ↔ 2.9B** | Перекладывает файлы LoRA на другую архитектуру по официальной схеме расширения. Получается обычная LoRA для любого интерфейса. Можно обработать сразу всю папку вместе с подпапками (при выходной папке структура подпапок сохраняется, прошлые результаты рядом с исходниками пропускаются). |
| **Анализ** | Анализаторы с HTML-отчётами, только чтение (подробнее ниже). |
| **Рецепт** | Цепочка шагов текстом (`Flat = merge ...`, потом `Final = bake model=$Flat ...`), при желании с удалением промежуточных файлов. Модели ищутся по имени в папке моделей, её подпапках и папке результатов (LoRA — в папке LoRA и подпапках); если имя встречается дважды, укажи подпапку: `sub/Model`. |
| **Перенос 2B ↔ 2.9B** | Переносит дельту файнтюна на другую архитектуру по карте блоков: по схеме `official`, по весам или по готовой карте. |
| **Карта блоков** | Строит и сохраняет карту 2B ↔ 2.9B. Режим `compare` сверяет карту, посчитанную по весам, со схемой. |
| **Инфо о модели** | Устройство чекпоинта: префикс, блоки, имена слоёв. |

### Анализ

| Анализатор | Что показывает |
|---|---|
| **Родитель** | От какой модели сделан файнтюн или мердж: рейтинг кандидатов с оценкой уверенности, «полосы» по блокам у поблочных мерджей и куда легло обучение. |
| **Семья** | Семейное древо: матрица расстояний, ближайшие родственники, тензоры, совпадающие бит в бит, и полностью совпадающие блоки (прямой родитель или потомок). |
| **Геном / состав** | Общие «гены» семейства (общий стиль и развилки веток) и **из чего собран каждый мердж**: с весами, в целом и по блокам. Находит и поблочные мерджи. |
| **Блоки** | Где модели отличаются от эталона: по блокам (12 вставленных блоков 2.9B отмечены), по типам слоёв и по частям вне блоков. Для 2.9B — трогали ли старые 28 блоков. Плюс проверка устройства файлов. |
| **Рецепт / метаданные** | Шаги AnimaMerger, записанные в файл, рецепты других мерджеров, параметры обучения LoRA и, по желанию, SHA256. Работает мгновенно: читаются только заголовки. |
| **Анализ LoRA** | Подробнее — сразу под таблицей. |

**Анализ LoRA.** Для одной LoRA показывает:
- силу (по желанию — относительно весов модели);
- где она работает: блоки и типы слоёв;
- эффективный ранг;
- параметры обучения;
- **теги датасета**: какие стоят на всех картинках и есть ли «мусорные» (подписи, вотермарки).

Для нескольких чекпоинтов одного обучения строит график по шагам или эпохам. На нём отмечено, где LoRA «выучилась» и где дальше растёт только сила — это риск пережога. Номера шагов берутся из имён файлов (`-step500`, `-000010`, `_e10`) или из метаданных; их можно задать и вручную.

Отчёты сохраняются в папку `reports/` в трёх видах: `.html` с графиками (наведи курсор — покажет значение), `.txt` и `.json`. Они же сразу показываются в интерфейсе. Считается на видеокарте, если она есть, иначе на процессоре.

**Профили (быстрый повторный анализ).** Родитель, Семья, Геном и Блоки по умолчанию работают по профилям моделей. Когда модель анализируется впервые, она читается один раз, и в папку `profiles/` сохраняется небольшой профиль (около 7 МБ для 2.9B): отпечаток файла, его устройство, точный хеш каждого тензора и фиксированная выборка из 4096 весов каждого тензора. Все следующие анализы читают только профили: если к семейству из десяти моделей добавилась одна новая, сканируется только она. Расстояния, доли и веса мерджей по профилям совпадают с точным расчётом примерно до 1–2%, одинаковые тензоры находятся точно. Переименованный или перенесённый файл сохраняет свой профиль, изменённый получает новый. Для точного расчёта включи **Точно, без профилей** (в командной строке `--exact`). Построить профили заранее (например, на ночь): **Анализ → Профили моделей → Построить профили для папки**, или `python anima_merger.py profile --models <папка>`. Там же видно, сколько профилей и сколько места они занимают, и есть кнопка очистки.

> Анализ LoRA смотрит на веса, поэтому выводы про недо- и переобучение — эвристики. Последнее слово за картинками на одном сиде.

## Правила по блокам и слоям (`deep`)

Как в рецептах Forge Neo: `0.5, L16-L27:mlp.layer1 mlp.layer2:0.2, L00-L27:adaln:0`
- число в начале — множитель по умолчанию;
- `Lx-Ly:шаблоны:значение` — диапазон блоков, подстроки имён слоёв через пробел и значение. Если подходит несколько правил, действует последнее;
- `adapter:*:0` / `adapter:self_attn:0.5` — правила для LLM-адаптера (`llm_adapter`);
- `^cross_attn` — шаблон ищется только с начала имени слоя. Простой `cross_attn` цепляет ещё и `adaln_modulation_cross_attn`. Если правило так захватывает слои adaLN, программа предупредит.

## Командная строка

Всё, что есть в интерфейсе, доступно и командами: `python anima_merger.py <команда> --help`

Команды: `merge`, `bake`, `extract`, `lora-merge`, `lora-convert`, `cross`, `map`, `info`, `parent`, `family`, `genome`, `blocks`, `meta`, `lora-info`, `profile`.

```
python anima_merger.py bake --model MyModel.safetensors --lora style.safetensors:0.7 --out MyModel+style.safetensors
python anima_merger.py lora-convert --lora папка_с_lora --to 40
python anima_merger.py lora-info --loras папка_обучения --model anima_base.safetensors
python anima_merger.py genome --models папка_моделей --base anima_base.safetensors
```

Язык сообщений в консоли задаёт `ANIMA_LANG=ru` или `en`. Порт интерфейса меняется через `ANIMA_MERGER_PORT`.

## Заметки

- При сохранении виден прогресс. Сначала пишется файл `имя.safetensors.part`, поэтому при обрыве недописанная модель никогда не окажется под настоящим именем.
- Результаты мерджа, вшивания и переноса хранят в заголовке, как они сделаны (поле `anima_merger`). Посмотреть можно во вкладке **«Рецепт / метаданные»**.
- Перенос между 2B и 2.9B приблизительный: после дообучения блоки 2.9B уже не равны блокам 2B. Всегда проверяй результат на одном сиде с сеткой значений M.
